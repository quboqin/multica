# Issue 原生广告创意协作

```text
Autopilot 创建父 Issue并分配素材小队
  -> Leader 查看成员职责和普通平台 Skill
  -> 采集智能体把真实结果写入父候选池
  -> 用户多选参考图并逐图固定文案
  -> 每张图创建一个独立创意工作 Issue
  -> Leader 按当前证据动态委派专业子 Issue
  -> Leader 验收并把三个尺寸发布到父结果看板
```

## AI 原生委派

平台不维护固定节点图、任务模板或单图/逐尺寸展开方式。小队名册会向 Leader 展示每个成员的
职责以及所绑定 Skill 的名称和描述。Leader 每次被唤醒时读取当前 Issue 证据，判断缺少什么，
再选择能力匹配的成员。实际父子 Issue 和评论记录就是这次执行的协作现场。

## 一图一分支

父 Issue 可以同时选择多张图。平台为每张图创建独立创意工作 Issue，固定候选 ID、逐图文案、
市场资源包版本和小队能力快照。图片之间可以并行；对某张结果提出调整时，只在该图下创建新
修订。不同图片的文案、参考文件、模型证据和 QC 不能串用。

## 平台快照

父 Issue 固定两类输入：

- 市场资源包及其已发布资源文件、二维码校验和关联文案库；
- 小队、Leader、成员职责以及各智能体当时绑定的普通平台 Skill。

已有 Issue 使用启动时快照，资源或 Skill 的后续修改只影响新批次或新修订。市场资源包管理
“用什么”，Skill 管理智能体“怎么做”。确定性工具放在 Skill references；图片和业务规范放在
可预览、可下载、可动态维护的市场资源文件中。

## App UI 替换

市场包可以有多条 `app_ui_reference`。候选图包含 App 界面时，分析智能体比较页面类型、组件
结构、信息密度和目标构图，记录所选资源文件 ID。图像编辑将候选图与选中的 AdaKami UI 一起
交给模型，禁止保留、仿造或改写竞品 UI。没有合适参考时应报告资源缺口。
