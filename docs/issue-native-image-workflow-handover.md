# 原生修图协作交接说明

生成阶段的并发模型、1/2/3 素材耗时口径和提效设计见
[`creative-workflow-performance-plan.md`](./creative-workflow-performance-plan.md)。

## 用户界面

一个创意批次对应一个父 Issue，业务操作区固定为两块：

- 素材候选池：承接真实采集和素材库导入，支持多选、逐图选择或精确编辑文案。
- 修图结果看板：每张候选按 V01-V03 展示三个创意，每个创意聚合三个尺寸，支持原图对比、
  接近全屏的看板预览、双侧单图放大、单尺寸下载、当前创意 ZIP、全批次 ZIP 和创意级精确调整。

智能体分析、提示词、生成证据、包装、返工和质检只放在子 Issue。父 Issue 不展示固定阶段、
内部编排说明或智能体长对话。

## 协作模型

Autopilot 创建父 Issue 并分配素材小队。Leader 使用普通平台 Skill `创意素材协作`，同时从小队
名册读取成员职责和各自绑定的普通平台 Skill，按当前证据动态委派。没有任务模板、节点编辑、
展开方式或专用编排资源类型。

真实采集是父 Issue 下的子 Issue。用户选中 N 张素材并固定逐图文案后，平台创建 N 个独立创意
工作 Issue。专业任务继续创建在对应图片下，多图可以并行，返工只影响目标图片、创意和尺寸。
每个工作 Issue 固定交付 V01-V03 三个创意，每个创意三个原生尺寸；Leader 只把全部验收通过的
九张图发布回父结果看板。

## 平台资源

“创意工厂”维护素材库、文案库和市场资源包。Skill 和小队在平台原生的 Skill、智能体、小队
页面维护：

- 素材库支持采集归档、本地文件/URL 导入、搜索、筛选、详情、预览和下载。
- 文案库支持 Excel 导入、在线编辑、审核和版本快照。
- 市场资源包支持页面编辑配置，动态添加、编辑、预览、下载和移除任意用途的文件。
- 当前市场包只服务 Indonesia；未来市场通过页面复制/新建资源包扩展。

仓库下的 `scripts/creative-platform-skills/*/SKILL.md` 是可版本控制的 Skill 源文件，不会因文件
变更自动出现在页面。bootstrap 发布后才会形成当前工作区的普通平台 Skill；随后还要把对应 Skill
绑定到智能体。工作区 Skill 列表展示全部已发布项，智能体详情只展示该智能体已绑定项。当前验收
工作区入口为 `http://localhost:3000/ad-creative-direct-pilot/skills`。

图片、品牌规范和合规材料是市场资源文件。方法、判断契约和确定性合成脚本是普通 Skill 的
references。父 Issue 快照包含市场包、关联文案库、小队、成员及成员 Skill，供所有后代任务
读取。

## App UI 参考

`app_ui_reference` 支持多条。当前已加入 AdaKami 1080×2160 新客首页。竞品素材含 App UI 时，
分析智能体选择最合适的参考图；图像编辑把候选图和该参考图同时作为模型输入，用真实 AdaKami
界面替换竞品 UI。用户后续可在市场包页面继续上传其他页面，无需改代码。

## Prime 合成

三个 Prime PNG 是完整贴图。方图、横图、竖图分别读取市场包对应文件。合成脚本来自 Prime
Skill 的 reference。不得新画二维码白底、移动条款或折叠二维码区域；最终二维码必须机器解码
并与已发布市场包快照一致。

## 验收条件

- AppGrowing 真实结果进入父 Issue 原生候选池。
- 多选 N 张素材后创建 N 个独立创意工作 Issue。
- 每张图有独立文案和资源快照，可只调整其中一个创意或一个尺寸。
- 包含竞品 UI 时能追溯所选 AdaKami UI 参考文件。
- 每张候选在父结果看板展示 V01-V03，每个创意展示三个尺寸、原图对比、文件名和下载入口。
- 旧创意任务表、Workspace/Agent MCP、专用编排配置和内置 Prime 二进制不参与运行。

最终三个尺寸由 Leader 发布回 `ADC-79`，文件名共享前缀
`april_AdaKami_Indonesia_question-repayment`。三个父 Issue 附件的二维码均可机器解码为
`https://www.adakami.id/termsandconditions`，没有新增二维码白底、底部白色色块或 Prime 折叠。

Issue 的最新人工决定，不能被更早的失败或风险文字覆盖。

## 2026-08-01 优化前性能基线

`ADC-92`（`a92832f7-8866-46fa-8795-671e6602d49b`）从真实候选池选择 2 张素材，分别完成 1 个
创意方向的三个尺寸，共发布 6 张图片。端到端用时 3 小时 50 分 35 秒；正常分支约 1 小时
43 分，另一个分支因图片任务限流、重复唤醒和返工放大到约 3 小时 30 分。

该版本是性能优化前的可回滚基线。主要耗时不在图片接口本身，而在 Leader 多次重复判断、专业
子 issue 排队、包装和 QC 的调度空档，以及失败任务缺少自动续跑。旧基线仍是一张素材只产出
1 个创意方向的三个尺寸。

当前交付契约已改为：每张入选素材生成 3 个有明确差异的创意变体，每个变体原生生成
`1080x1080`、`1200x628`、`800x1000` 三个尺寸，即每张素材交付 9 张成图。单张素材目标为
20-30 分钟；同时选择 3 张素材时按素材公平并发，目标仍为 20-30 分钟完成 3 套。图片任务并发
上限先设为 5，为上游最高 6 路额度保留 1 路余量。

执行采用母版流水线：方案智能体一次规划 V01-V03；Leader 一次创建三个变体图像编辑 Issue；
每个变体智能体先生成 `1080x1080` 母版，通过后立即在同一个 Issue 内用 `image edit-batch` 并发
生成 `1200x628` 和 `800x1000` 原生重排。九张底图齐备后，一个 Prime Issue 批量包装九张，
一个 QC Issue 批量验收九张。Leader 每次唤醒批量创建所有已满足依赖的任务，创建后立即退出，
由子 Issue 完成事件继续驱动。

`图像编辑智能体.max_concurrent_tasks=5` 控制实际图像请求并发。2026-08-02 真实 8 路探测确认
provider 硬上限为 6：6 路成功、2 路明确返回并发 429。生产静态配置继续用 5，为人工微调、重试
或其他批次保留 1 路；daemon 总任务上限保持 8，使 Leader、方案、Prime 和 QC 可以与五路图像
请求共享剩余执行位，同时避免文本任务无限堆积。CLI 对 408、429、5xx 和网络中断最多自动尝试 3 次，并把实际尝试次数
写入证据。完整证据、配置和 1/2/3 素材耗时见本文开头链接的提效方案。

## 2026-08-02 结果追溯与精准返工

结果看板不再只依赖附件文件名推断来源。迁移 252 新增结构化交付记录，将父 Issue、候选素材、
原创意工作 Issue、V01-V03、尺寸、修订号、无品牌底图、Prime 成图、包装证据和 QC Issue 明确
关联。父 Issue 因而能稳定展示“竞品原图 / 当前成图”对比；旧附件仍保留文件名兼容解析，不影响
已有 Issue。

每张成图提供“调整当前创意”入口，业务用户可在同一个弹窗中查看竞品原图和当前成图，并选择：

- 仅当前尺寸：只把当前尺寸的成图和对应无品牌底图交给 Leader；另外两个尺寸继续沿用。
- 当前创意三尺寸：把同一变体的三个最新尺寸交给 Leader，共享修改要求但仍按尺寸原生处理。

平台先创建结构化调整请求，再创建直属于原创意工作 Issue 的调整子 Issue，并在 Issue 创建事务
内写入 `metadata.workflow=creative_adjustment`、目标候选、变体、尺寸范围、精确附件 ID 和修订号。
Leader 根据该 metadata 识别返工，不重新跑完整 3 x 3。图像编辑从上一个无品牌底图继续修改，
Prime 成图只作为视觉对照，避免把二维码、条款和 Prime 边框送回生成模型造成二次绘制。包装和
QC 分别只处理本次的一张或三张输出。

Leader 发布通过的成图后执行 `multica creative delivery register`，把新附件登记为下一修订；
结果看板只把每个变体和尺寸的最高修订作为当前版本，旧版本不删除，仍可审计和回看。`ADC-135`
已回填 9 条 R4 交付记录，覆盖 3 个变体和 3 个尺寸，可直接用于页面验收。

## GPT-5.6 智能体配置

Codex 智能体模型下拉提供通用 `GPT-5.6`、旗舰 `GPT-5.6 Sol`、均衡型 `GPT-5.6 Terra` 和
高吞吐型 `GPT-5.6 Luna`，并保留 `GPT-5.5`。平台优先采用 daemon 的真实模型目录：当前 Sol
和 Terra 支持 `low / medium / high / xhigh / max / ultra`，Sol 默认 `low`；Luna 支持
`low / medium / high / xhigh / max`；通用 `gpt-5.6` 使用官方 API 的
`none / low / medium / high / xhigh / max`，默认 `medium`。runtime 未枚举型号时平台也会使用这套
官方 API 档位兜底。现有素材小队不会被自动切换，用户可在智能体页面逐个选择模型和努力程度。

结果看板按一张来源素材一屏比较：第一行横向切换素材，第二行用缩略图切换 V01-V03，主体只并排
显示竞品原图和当前创意，保证图片完整、清晰且文件名互不覆盖。当前创意可直接切换三个尺寸；较窄
窗口横向滚动，不纵向堆叠素材或创意。点击原图或成图仍可进入大图预览。

放大看板使用 96vh 独立工作区：文件名、统计和下载/调整操作共用顶部工具栏，双栏图片自动占满剩余
高度并保持完整比例，素材/创意选择器不产生纵向滚动，文件信息固定在图片下方且不覆盖画面。

## 2026-08-02 3 x 3 批处理提效实现

平台新增的都是通用原语：`image edit-batch`、`issue create-batch`、`issue children --compact`、
跨进程图片槽位和结构化交付登记。3 个创意、3 个尺寸、AdaKami Prime、安全区恢复和 QC 依赖仍由
工作区 Skill 描述，业务可在平台修改 Skill 与资源包，不需要改服务端代码。

当前初次生产拓扑固定为一个方案 Issue、三个变体生产 Issue、一个九图 Prime Issue和一个九图 QC
Issue。图片 provider 已实测 6 路硬上限，生产使用 5 路；Agent 总任务上限保持 8。方案与 QC 使用
`gpt-5.6-terra / medium`，图片生产与确定性 Prime 包装使用 `gpt-5.6-terra / low`。Luna 在本机
真实任务中出现语义活动超时，当前不作为这条工作流的生产默认值。

`ADC-202` 现场确认方案由约 7分30秒降到 4分10秒，九图 Prime 由约 5分37秒降到 2分34秒，修复
契约后的九图 QC 约 2分29秒。一次真实 QC 发现 7 张左上品牌碰撞后，Leader 将失败项按变体聚合为
`ADC-214/215/216` 三个恢复 Issue；7 次真实图片调用在五槽下 9分46秒完成，再由单个七图 Prime
`ADC-217` 和单个七图 QC `ADC-218` 收口。V03 已通过的横竖两张全程沿用。

竖图 provider 偶发忽略 4:5 请求时，规范化 reference 是唯一比例判定：首轮 1024x1280，失败后仅
允许 1280x1600 再试一次；两次都返回近 2:3 时，使用最多 21% 的连续边缘淡化延展保留完整主体，
不裁切、不拉伸、不继续消耗模型调用。Prime/QC 并发下载会先显式创建输入目录，避免 Windows 首次
建目录竞态；QC 直接兼容 Prime 原生 manifest 与 compose result，不再创建证据转换任务。

恢复链路最终实测：`ADC-214/215/216` 七次真实修图在五槽下 9分46秒完成；七图 Prime
`ADC-217` 用时 3分57秒；七图 QC `ADC-218` 用时 3分30秒且机器、视觉均 7/7 通过；Leader 发布
用时 3分43秒。`ADC-201` 已有 9 张最终附件和 9 个完整交付键，V03 已通过的横版、竖版沿用首轮，
其余七张使用恢复版本。

CLI 的 `creative materials` 现在保留 API 返回的 `deliveries` 和 `adjustments`。Leader 发布
前必须把父 Issue 已登记结果与本轮结果合并，补登记任何被复用但尚未登记的尺寸；发布后重新读取并
验证完整九键，同时将创意工作 Issue 置为 `done` 并复核。这样局部恢复不会再因 CLI 丢字段而遗漏
复用结果。

本次修正后启动到发布共 1小时44分06秒，包含运行中修改 Skill、修复工具契约和真实七图返工，不是
稳定路径基线。依据各阶段实测和图片波次模型，当前无返工单素材仍按 26-30 分钟估算；2 张为
32-40 分钟，3 张为 38-50 分钟。下一次应使用不改代码、不改 Skill 的冷启动样例验证该区间。

## 2026-08-03 Prime 硬区与早期质检策略修正

`ADC-219/220` 暴露出一处规则回归：市场包原本提供的是 Logo、条款二维码、商店徽章、监管标识等
真实 `hard_regions` 坐标，但方案、生产和 QC 又把顶部最低边界、底部最高边界合并成了两条全宽
硬带。结果是图片模型被迫压缩版式，QC 把没有真实遮挡的内容判失败，安全区返工还可能删掉表格、
人物和其他关键内容。这不是图片 provider 的随机性，而是工作流合同被错误扩大。

当前修正后的合同：

- 市场包 v50 明确 `guide_policy=hard_regions_only`；顶部/底部数值只用于生成上下文放大图，不参与
  失败判定。
- 方案 v12 和图像编辑 v20 对每个尺寸逐一读取实际 region ID 与坐标。模型只需让这些矩形延续
  自然低纹理背景，矩形之外正常构图；禁止再生成全宽顶部/底部避让带。
- 获批文案、金额、期限、利率、`information_mechanism`、`must_preserve`、表格、人物和关键卡片
  是内容硬门槛。尺寸重排和返工只能移动，不能删除、概括、改写或换主题。
- Prime 继续由确定性脚本原样覆盖，模型不得生成 Logo、条款、二维码、商店徽章或监管标识。
- QC v13 只把文件/尺寸/包装/二维码失败、Prime 缺失或不可读、竞品残留、关键内容删改或实际遮挡、
  严重破图列为 `blocking_failures`。一般构图、拥挤和非关键视觉偏差进入 `quality_warnings`，使用
  `QC PASS WITH WARNINGS` 正常发布，由用户决定是否自然语言调整。
- Leader v23 只对 `blocking_failures` 返工；观察模式遇到硬问题直接停在现场，不自动补救。
