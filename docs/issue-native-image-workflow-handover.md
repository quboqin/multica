# 原生修图协作交接说明

## 用户界面

一个创意批次对应一个父 Issue，业务操作区固定为两块：

- 素材候选池：承接真实采集和素材库导入，支持多选、逐图选择或精确编辑文案。
- 修图结果看板：每张候选按 V01-V03 展示三个创意，每个创意聚合三个尺寸，支持原图对比、
  单尺寸下载、当前创意 ZIP、全批次 ZIP 和创意级精确调整。

智能体分析、提示词、生成证据、包装、返工和质检只放在子 Issue。父 Issue 不展示固定阶段、
内部编排说明或智能体长对话。

## 协作模型

Autopilot 创建父 Issue 并分配素材小队。Leader 使用普通平台 Skill `创意素材协作`，同时从小队
名册读取成员职责和各自绑定的普通平台 Skill，按当前证据动态委派。没有任务模板、节点编辑、
展开方式或专用编排资源类型。

真实采集是父 Issue 下的子 Issue。用户选中 N 张素材并固定逐图文案后，平台创建 N 个独立创意
工作 Issue。专业任务继续创建在对应图片下，多图可以并行，返工只影响目标图片、创意和尺寸。
每个工作 Issue 固定交付 V01-V03 三个创意，每个创意三个原生尺寸；Leader 只把全部验收通过的
九张图发布回父结果看板。

## 平台资源

“创意工厂”维护素材库、文案库和市场资源包。Skill 和小队在平台原生的 Skill、智能体、小队
页面维护：

- 素材库支持采集归档、本地文件/URL 导入、搜索、筛选、详情、预览和下载。
- 文案库支持 Excel 导入、在线编辑、审核和版本快照。
- 市场资源包支持页面编辑配置，动态添加、编辑、预览、下载和移除任意用途的文件。
- 当前市场包只服务 Indonesia；未来市场通过页面复制/新建资源包扩展。

图片、品牌规范和合规材料是市场资源文件。方法、判断契约和确定性合成脚本是普通 Skill 的
references。父 Issue 快照包含市场包、关联文案库、小队、成员及成员 Skill，供所有后代任务
读取。

## App UI 参考

`app_ui_reference` 支持多条。当前已加入 AdaKami 1080×2160 新客首页。竞品素材含 App UI 时，
分析智能体选择最合适的参考图；图像编辑把候选图和该参考图同时作为模型输入，用真实 AdaKami
界面替换竞品 UI。用户后续可在市场包页面继续上传其他页面，无需改代码。

## Prime 合成

三个 Prime PNG 是完整贴图。方图、横图、竖图分别读取市场包对应文件。合成脚本来自 Prime
Skill 的 reference。不得新画二维码白底、移动条款或折叠二维码区域；最终二维码必须机器解码
并与已发布市场包快照一致。

## 验收条件

- AppGrowing 真实结果进入父 Issue 原生候选池。
- 多选 N 张素材后创建 N 个独立创意工作 Issue。
- 每张图有独立文案和资源快照，可只调整其中一个创意或一个尺寸。
- 包含竞品 UI 时能追溯所选 AdaKami UI 参考文件。
- 每张候选在父结果看板展示 V01-V03，每个创意展示三个尺寸、原图对比、文件名和下载入口。
- 旧创意任务表、Workspace/Agent MCP、专用编排配置和内置 Prime 二进制不参与运行。

## 2026-08-01 真实验收样例

验收入口为 `ADC-79`（`2026-08-01 印尼素材采集与修图协作验收 v6`）。完整链路如下：

```text
ADC-79 父候选池 / 结果看板
  ADC-80 AppGrowing 真实采集：23 条候选
  ADC-81 入选 Adapundi 素材的独立创意工作
    ADC-82 参考分析
    ADC-83 生成方案
    ADC-84 / ADC-85 / ADC-86 三尺寸无品牌底图
    ADC-87 / ADC-88 / ADC-89 三尺寸 Prime 包装
    ADC-90 独立质量验收：三尺寸 QC PASS
```

最终三个尺寸由 Leader 发布回 `ADC-79`，文件名共享前缀
`april_AdaKami_Indonesia_question-repayment`。三个父 Issue 附件的二维码均可机器解码为
`https://www.adakami.id/termsandconditions`，没有新增二维码白底、底部白色色块或 Prime 折叠。

候选状态在发布后仍保留为 `selected`，这是为了让用户继续从结果看板进入“调整这张图”；最终
成图是否进入结果看板由父 Issue 上符合命名规则的 PNG 附件决定，不通过改写候选状态表达。

运行中若图片模型限流，应先检查当前专业子 Issue 是否已经收到模型输出附件。已有成功输出时
直接继续尺寸适配、Prime 包装和 QC；只有确实没有有效输出时才重试模型。Leader 必须读取子
Issue 的最新人工决定，不能被更早的失败或风险文字覆盖。

## 2026-08-01 优化前性能基线

`ADC-92`（`a92832f7-8866-46fa-8795-671e6602d49b`）从真实候选池选择 2 张素材，分别完成 1 个
创意方向的三个尺寸，共发布 6 张图片。端到端用时 3 小时 50 分 35 秒；正常分支约 1 小时
43 分，另一个分支因图片任务限流、重复唤醒和返工放大到约 3 小时 30 分。

该版本是性能优化前的可回滚基线。主要耗时不在图片接口本身，而在 Leader 多次重复判断、专业
子 issue 排队、包装和 QC 的调度空档，以及失败任务缺少自动续跑。旧基线仍是一张素材只产出
1 个创意方向的三个尺寸。

当前交付契约已改为：每张入选素材生成 3 个有明确差异的创意变体，每个变体原生生成
`1080x1080`、`1200x628`、`800x1000` 三个尺寸，即每张素材交付 9 张成图。单张素材目标为
20-30 分钟；同时选择 3 张素材时按素材公平并发，目标仍为 20-30 分钟完成 3 套。图片任务并发
上限先设为 5，为上游最高 6 路额度保留 1 路余量。

执行采用母版流水线：方案智能体一次规划 V01-V03；Leader 同时委派三个 `1080x1080` 母版；
每个母版通过后，立即以母版为第一参考同时委派 `1200x628` 和 `800x1000` 原生重排。一个 Prime
Issue 批量包装同一变体三个尺寸，一个 QC Issue 批量验收同一变体三个尺寸。Leader 每次唤醒
批量创建所有已满足依赖的任务，创建后立即退出，由子 Issue 完成事件继续驱动。

`图像编辑智能体.max_concurrent_tasks=5` 控制实际图像请求并发；daemon 总任务上限为 8，使
Leader、Prime 和 QC 可以与五路图像任务同时运行，不会把非图像任务挤出调度。CLI 对 408、429、
5xx 和网络中断最多自动尝试 3 次，并把实际尝试次数写入证据。

## 2026-08-01 真实 3 x 3 验收

`ADC-135` 从真实 AppGrowing Easycash Indonesia 多页采集开始，选择候选
`19c9a621-51c2-4dad-9529-c4544865066e`，经像素利益点分析和 Excel v15 审核文案进入 `ADC-140`。
Leader 同秒创建三个方形母版，后续按母版完成状态批量创建六个原生重排；实测出现五个图像任务
同时运行，没有 429。三个变体各由一个 Prime Issue 批量包装三尺寸、一个 QC Issue独立验收
三尺寸，最后 9 张 PNG 一次发布到 `ADC-135` 结果看板。

9 个文件名均包含 V01-V03 和尺寸，实际像素为三组 `1080x1080`、`1200x628`、`800x1000`；
二维码全部重新解码为市场包批准 payload，Prime 完整，无二维码白块和底部白带。三套视觉分别为
住宅建设、家庭预算和金融信息图，不是同图换色。

`ADC-140` 启动到 9 张发布实测约 61 分 9 秒，尚未达到 20-30 分钟目标。9 张底图齐套约 39 分
55 秒，最后 QC 约 57 分 17 秒。主要新增成本是三处真实质量返工和 Leader/专业智能体重复查询
平台读取命令。当前已补 `multica issue children <issue-id> --output json`，Leader 不再拉全工作区
Issue 筛直接子项；Prime/QC Skill 也固定用明确命令并行下载六个附件。下一轮以本次记录为基线，
继续减少图像调用前后准备和无动作唤醒，不通过降低 QC 或跳过原生尺寸换速度。

## 2026-08-02 结果追溯与精准返工

结果看板不再只依赖附件文件名推断来源。迁移 252 新增结构化交付记录，将父 Issue、候选素材、
原创意工作 Issue、V01-V03、尺寸、修订号、无品牌底图、Prime 成图、包装证据和 QC Issue 明确
关联。父 Issue 因而能稳定展示“竞品原图 / 当前成图”对比；旧附件仍保留文件名兼容解析，不影响
已有 Issue。

每张成图提供“调整当前创意”入口，业务用户可在同一个弹窗中查看竞品原图和当前成图，并选择：

- 仅当前尺寸：只把当前尺寸的成图和对应无品牌底图交给 Leader；另外两个尺寸继续沿用。
- 当前创意三尺寸：把同一变体的三个最新尺寸交给 Leader，共享修改要求但仍按尺寸原生处理。

平台先创建结构化调整请求，再创建直属于原创意工作 Issue 的调整子 Issue，并在 Issue 创建事务
内写入 `metadata.workflow=creative_adjustment`、目标候选、变体、尺寸范围、精确附件 ID 和修订号。
Leader 根据该 metadata 识别返工，不重新跑完整 3 x 3。图像编辑从上一个无品牌底图继续修改，
Prime 成图只作为视觉对照，避免把二维码、条款和 Prime 边框送回生成模型造成二次绘制。包装和
QC 分别只处理本次的一张或三张输出。

Leader 发布通过的成图后执行 `multica creative delivery register`，把新附件登记为下一修订；
结果看板只把每个变体和尺寸的最高修订作为当前版本，旧版本不删除，仍可审计和回看。`ADC-135`
已回填 9 条 R4 交付记录，覆盖 3 个变体和 3 个尺寸，可直接用于页面验收。
