# Creative Order Planning Source Map

| Contract | Source |
| --- | --- |
| `multica creative order get` returns the item copy snapshot, source-analysis reference, frozen input snapshot, variants, and assets | `server/cmd/multica/cmd_creative_domain.go:runCreativeOrderGet`, `server/internal/handler/creative_domain.go:GetCreativeOrder` |
| `multica creative order variant-put` writes the structured V01-V03 briefs | `server/cmd/multica/cmd_creative_domain.go:runCreativeOrderVariantPut`, `server/internal/handler/creative_domain.go:UpsertCreativeOrderVariant` |
| Production expected sizes come from the frozen order snapshot, with the three standard delivery sizes as the default | `server/internal/handler/creative_domain.go:expectedCreativeVariantSizes`, `server/internal/handler/creative_domain.go:creativeOrderSnapshotExpectedSizes` |
| Variant writes preserve planner-supplied derived execution but the server overwrites `creative_contract.parent_direction` and its SHA-256 from the immutable order-item direction summary | `server/internal/handler/creative_domain.go:bindCreativeOrderVariantParentContract`, `server/internal/handler/creative_domain.go:UpsertCreativeOrderVariant` |
| `multica task by-source list` returns all items for an Agent and evidence pair; callers compare item keys individually | `server/cmd/multica/cmd_task.go`, `server/internal/service/task.go:ListDirectTasksByEvidence` |
| Production fanout requires source evidence, `creative_production`, matching item ref, order trace UUIDs, a variant ID, revision, and expected sizes | `server/internal/handler/task_fanout.go:validateCreativeTaskFanoutContext`, `server/internal/handler/task_fanout.go:validateCreativeProductionTaskContext` |
| Production fanout context is normalized to the current Variant revision before enqueue; `revision=0` and stale item keys are not accepted as final task identity | `server/internal/handler/task_fanout.go:normalizeCreativeProductionFanoutItem`, `server/internal/handler/task_fanout.go:validateCreativeProductionTaskContext` |
| Native production fanout is idempotent for active work by target Agent, evidence pair, and variant/revision item key | `server/internal/service/task.go:EnqueueDirectTaskFanout`, `server/internal/service/task.go:directTaskItemKey` |
| Frozen repayment-plan entries, selected repayment values, and calculation results are approved first-party financial facts for Variant briefs; Planner must not invent `COPY_SNAPSHOT_FINANCIAL_TOKEN_MISMATCH` for these values | `scripts/creative-platform-skills/ad-creative-plan/SKILL.md:输入真值`, `scripts/creative-platform-skills/ad-creative-production/references/validate_copy_snapshot.py:approved_text` |
| V01-V03 briefs must include high-salience anti-copy changes and a visual identity strategy so production cannot be a text-only edit of the reference | `scripts/creative-platform-skills/ad-creative-plan/SKILL.md:方案合同`, `scripts/creative-platform-skills/ad-creative-production/references/validate_copy_snapshot.py:validate_redesign_prompt_guard` |
| Each brief states the Prime business purpose and how the actual Prime context participates in the visual system; deterministic compose remains the source of official Prime text and components | `scripts/creative-platform-skills/ad-creative-plan/SKILL.md:Prime 的视觉意义`, `scripts/creative-platform-skills/ad-creative-production/SKILL.md:Prime 参与构图` |
| Variant briefs carry structured creative decisions only; the production Agent writes the final prompt per size and brief does not duplicate it, the repayment table, or source-audit prose | `scripts/creative-platform-skills/ad-creative-plan/SKILL.md:方案合同` |

Copy selection and block filling are completed by pre-adaptation. This Skill's runtime source is only the order item's frozen schema-v3 `copy_snapshot`; mutable copy-library resources are intentionally excluded.
